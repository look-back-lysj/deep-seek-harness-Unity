# 作者上架、可靠分发与市场扩展接口

日期：2026-09-28。状态：下一阶段设计，**尚未实现**。本文描述市场私有接口，不能宣称是 DSH／dsh-std／Mojobox 已有公共标准。实施顺序与验收见 [下一阶段计划](NEXT-STAGE-PLAN.md)。

## 1. 什么叫「正常上架并安装」

作者交资料和能运行的包，团队核对授权、身份、官方加载声明与使用方法；通过校验后生成市场目录。用户选中目录里的确切版本，下载校验后的同一份文件交给**官方 DSH 插件管理器**，最后展示实际安装／启用／重启结果。市场不在新手电脑上临时编译未知仓库，不让模型自由写命令补装。

上架资料不等于程序本身：介绍 ZIP 是图文与许可资料，可供作者编辑；插件 tgz 是官方能安装的程序文件；市场目录是把两者和版本、来源、兼容证据对应起来的索引。三个入口与错误提示必须分开。

## 2. 作者与团队分工：两条路径都支持

| 路径 | 作者提供 | 团队负责 | 好处与限制 |
| --- | --- | --- | --- |
| A 优先：作者发行包 | 固定版本标准 bundle tgz、仓库/固定tag或commit、许可证与再分发条件、使用入口、说明与截图、依赖/脚本/平台信息 | 校验作者身份声明与授权材料、测试目标宿主、计算实际摘要、镜像原字节、生成目录 | 不替作者维护构建，最快；仅有源码 ZIP 或缺 bundle 声明不能冒充可安装 |
| B 特殊：团队构建 | 可使用与分发的授权/许可证、固定源码commit、源码子目录、构建说明、锁文件、依赖与资源说明 | 审核独立构建配方，在临时 CI 环境构建，记录工具链/平台/输入输出；测试成品再发布 | 能兼容没有发行包的合作作者；团队承担重建、许可、版本与后续升级成本 |

只从 GitHub/Gitee 拉一个 main 分支不满足任何一路。源码地址用于追溯；下载入口必须指向固定产物。GitHub 与 Gitee 代码镜像也**不会自动同步 Release 附件**，须逐个上传并验证实际返回文件。

构建 B 不在市场 Host 内执行；作者 README 是说明，不是可直接运行的授权脚本。CI 对不可信来源不注入发布密钥，构建与带凭据发布分离；精确依赖与获准的生命周期脚本由配方列出，资源和执行时间有上限。失败保留记录而不上传半成品。

重新构建得到不同字节，应是新的构建产物记录，不能登记为 A 原包的同摘要镜像。若为普通插件补 wrapper，wrapper 使用独立包身份／版本并保留 `derivedFrom`；原作者署名、代码许可与通知保留，不在客户端下载后偷偷插入用户层 patch。

## 3. 作者交付模板与审核流程

下一模型创建真实可校验模板，建议路径：`catalog-source/templates/author-submission.json`、`release.json`、`build-recipe.json`、`presentation.json`，以及一份 `docs/contributing/AUTHOR-ONBOARDING.md`。模板不是生产数据，CI 拒绝占位地址进入正式目录。

| 信息组 | 必需内容 | 不齐时怎样处理 |
| --- | --- | --- |
| 身份与授权 | 目录插件 ID、实际 npm 包名、版本、原作者、维护联系渠道、仓库、许可证、再分发依据；借用图文也要有来源 | 未确立再分发条件不镜像；可保留内部候选，不标已合作／已上架 |
| 用户说明 | 中文友好名称、一句话用途、适合谁、使用入口、必要设置、限制、截图/替代文本、故障求助位置 | 可以不精选，但不能靠虚构说明补齐；无使用入口无法完成新手体验验收 |
| 制品与加载 | tgz 或授权源码配方；包内 package.json、有效 dsh.bundle.patch 及所引用文件；Host/Client entry/exports | 缺 bundle 可展示但不可一键装；用作者修正或独立 wrapper 路线解决 |
| 环境与影响 | DSH 范围、系统/架构、原生依赖、安装脚本、账号/网络/模型/额外资源要求、默认启用意图、设置保存位置及已知卸载/降级限制 | 不猜权限与数据行为；不能证明的危险动作不开放 |
| 发行与来源 | 固定 release/tag/commit、每个真实下载 URL、大小、实际 SHA256、可追溯发布时间、变更说明 | 浮动链接或同名异字节拒绝合并；缺可靠发布时间不参与最近发布排序 |
| 验证与推荐 | 实际宿主/系统/架构、测试动作、结果、证据关联；团队推荐理由、负责人、位置、期限 | 格式解析仅 Parsed；无运行证明标 unverified；推荐不等于认证 |

流程：资料接收（市场导出或私下均可）→创建候选记录→授权与静态校验→隔离环境官方安装/使用→内容审阅→团队批准→发布固定制品/镜像→生成并验证目录→更新 latest 指针。MVP 不创建作者在线账号／认领／自动发布接口。

改介绍可单独提交 Presentation 修订；程序变更必须产生新的 ReleaseRecord。撤回介绍、撤回推荐、撤回兼容证据、停止分发版本是四种不同操作，不互相代替。成员更新内容不要求编辑市场源代码。

## 4. 数据分层与升级规则

以下类型是设计合同，G0 冻结实际字段及序列化规则后实施；字段建议不是凭空扩展公共对象。

| 市场私有对象 | 关键字段与不变量 |
| --- | --- |
| `ReleaseRecord` | schemaVersion、releaseId、pluginId、packageName、version、artifactDigest、size、metadataRef、provenance、targets、declaredDshRange、publishedAt。releaseId 由身份与摘要稳定确定；记录冻结后不改字节或身份 |
| `ReleaseProvenance` | 判别 author-release／team-build；原仓/固定commit或release证据、许可引用；team-build 额外 sourceSubdir、lockDigest、recipeDigest、toolchain、target、buildRun、derivedFrom。授权与可重现构建证据分别记录，不把记录存在等同可重现 |
| `CatalogDelivery` | deliveryRevision、releaseId、package/version/digest/size、sources[]。每源含稳定 sourceId、kind、确切定位、provider、最后验证结果；重新指向另一个地址产生新修订 |
| `CatalogPresentation` | presentationRevision、pluginId、适用版本范围、标题/摘要/正文/图/使用说明、来源署名、媒体摘要；不允许覆盖制品身份和真实安装状态 |
| `RecommendationRecord` | id、pluginId 或组合ID、适用版本、reason、placement、rank、curator、effectiveAt/expiresAt。独立于 distribution，不改 builtin/recommended/external 等公共语义 |
| `ReleaseStatusRecord` | releaseId、序号、active/withdrawn、reason、effectiveAt；是可追加生命周期记录，不改冻结制品。撤回阻止新计划；已装用户收到准确提示，不自动卸载 |
| `EvidenceReference` | 引用原始公共证据字节及摘要，按其版本校验；当前环境的最终展示由 Host 结合证据范围计算，不能信任条目自报 verified |
| `CatalogRevision` | 单调发布序号、修订ID、生成时间、受控源身份、各对象内容摘要、支持格式版本；快照整体验证后原子切换，失败留上份可用快照 |

摘要表示「内容指纹」，只证明下载字节与被信任目录一致，不证明软件一定无恶意，也不等于签名。初期来源信任来自团队认可的目录配置和 HTTPS 路径约束；没有真实签名过程不能显示已验签。发布序号只能拒绝已经见过的新版本之后又回退到更旧目录，不能知道离线时是否发生新撤回，更不能在清空本地记录后证明永不回退；这些限制写入状态说明。

### 官方包与社区公共格式必须分开

现有 `MarketPluginRecord` 强制带 `manifestDigest + manifest`，会使只使用官方标准的作者被迫编造社区 Manifest。计划引入明确的私有分支：

- `official-bundle`：保存从实际制品提取的官方 package.json / dsh 元数据引用和原始摘要，验证官方格式、路径和文件存在；官方没有的字段由市场私有展示资料补充，不伪造 dsh-std。
- `dsh-std`：保存真实 Manifest 原字节及摘要，并按固定协议修订验证；只有实际满足这一路才能声明符合它。

公共 Mojobox Catalog/Pack/Lock/Evidence 的类型和字段保持原样。当前固定 PackLock source 只支持精确 npm 定位；只有 GitHub tgz 的插件可先按单插件安装，不能塞进假的 npm 坐标。为保留未来全家桶组合能力，可定义**明确不同 kind 的市场私有 `MarketCollection`**：引用 releaseId 与精确摘要、必选/可选项、默认启用意图及完整执行依赖。其预检和任务共用核心，不能将该私有组合导出成声称合规的公共 Pack。

公共 Pack 路线与私有组合路线均留验收：公共路线必须有真实可解析 npm 精确条目；私有路线不受该公共字段误用约束。已定「套餐按确认后版本调整」「无关项继续」对两者相同；没有完整关系说明时，不臆造依赖或宣称能安全并行。

升级建议：发布新的私有市场索引版本，保持旧版本只读兼容；新生成器输出新格式。旧缓存先解析/校验再迁移，不原地改写公共原始字节；旧进行中计划继续绑定旧字节，若生命周期已撤回则暂停核对；版本无法解释时拒绝该快照并保留上份，不默认为空市场。

## 5. 下载与官方安装合同

计划中冻结的下载对象至少包含：releaseId、目标 package/version/digest/size、deliveryRevision、**来源描述数组及摘要**、允许的镜像次序、兼容/撤回状态证据。`sourceRef` 不能只是一串被适配器忽略的 ID。

下载结果记录实际尝试 sourceId、阶段/失败原因、最终 URL 的安全核验、字节摘要和大小、缓存引用。安装只消费已验证的同一个本地 tgz；不要校验 A 却把远端 B 链接交给安装器重新下载。

多源行为：连接超时、限流或不可达时，可以切换到**用户确认清单内**同摘要镜像；新地址需重新预检。内容摘要错误标记该源不可信并保留诊断，不静默忽略校验；如政策允许再尝试另一已确认源，仍验证完全相同的预期摘要，界面说明先前失败。禁止退回旧版、浮动分支、同名包或自行替换摘要。

保持 `delivery/security.ts` 的协议、重定向、DNS/IP、私网、本地路径白名单和大小/超时约束；每次重定向重新验证，不因 provider 名为 github/gitee 就无条件放行。公开插件安装不要求 GitHub 登录；不得把 GitHub token 编进目录或 URL。对本轮本机研究的下载遵守用户 Motrix 约定；未来产品自己的下载模块不因此依赖用户安装 Motrix。

缓存以内容摘要命名，临时下载完成校验后才变成可引用对象。顶层 tgz 校验不保证所有 npm 传递依赖完全锁定；如需保证完整离线闭包，那是另一个后续交付，不能用「双镜像」冒充离线可用。

### 建议的团队内容仓结构

```text
catalog-source/
  schemas/                 # 市场私有 schema，不复制修改公共 schema
  plugins/<id>/            # release、展示、授权索引和生命周期记录
  recommendations/         # 人工精选及理由
  collections/             # 公共 Pack 引用或明确私有组合
  build-recipes/           # 已审核的固定源码构建配方
  templates/               # 作者提交模板
scripts/catalog/           # 校验、制品检查、目录生成和镜像一致性
```

制品发布顺序：生成 tgz→记录实际字节→独立环境验证→上传 GitHub/Gitee 固定附件→重新获取核对大小/摘要→发布不可变目录修订→最后更新 latest。可达性验证不能只看 HTTP 200，要排除 HTML 登录页、网盘提示页和错误文本。

本轮新建的私人源码仓只存工程与文档。未来内容仓具体 owner、名称、地址、维护权限、公开范围待真实团队决定；不预造生产 URL、不擅自公开私人仓、不向作者发送消息。

## 6. 扩展机制：一份合同，两种接法

用户已选择两种都支持：

1. 团队模块随市场构建，经内置适配器登记，便于共同发布。
2. 合作作者以独立标准 DSH 插件安装／升级／停用，经官方 Client 依赖服务登记，**不重新构建市场即可生效**。

共同注册表负责版本、ID、能力、位置和清理；来源适配器负责接入时机。目录 JSON 仅是资料，绝不加载其中的 URL JavaScript。官方既有 `main` 和 `sidebar.panellist` 继续用于 EAC 面板本身；官方 `plugins.detail.*` 属于官方插件页，不当作 EAC 详情槽位。

### 拟定的五类私有位置

| 候选名称 | 展示方式 | 明确边界 |
| --- | --- | --- |
| `eac.market.home.supplemental.section` | 发现页核心精选/搜索之后的补充 section | 标提供方，可接教程/专题；不覆盖核心推荐/排序，不借扩展伪造兼容标志 |
| `eac.market.extension.more` | 更多→扩展工具 | 菜单文本/图标/目标页由市场渲染；没有贡献隐藏分组，不新增第四主导航 |
| `eac.market.extension.page` | 带标题和返回入口的二级页 | 以扩展ID命名 key，保留三主导航，不替换 EAC 主页面或 DSH 主面板 |
| `eac.market.detail.section` | 指定插件详情核心信息之后 | 与当前 plugin/release 绑定；不能修改版本、安装状态、验证或核心动作 |
| `eac.market.author.tool` | 作者工具中的补充工具 | 仅预览草稿改动，核心保存仍带 expectedRevision；不暗接在线发布 |

这些键由下一轮代码声明，当前不存在。具体 list/keyed/children 类型按当时官方 slots 真实类型实现；不会先在文档里发明一个调用参数再让官方库迁就。

### 合同与所有权

`ExtensionDefinition` 建议包含 id、version、apiVersion、marketRange、dshRange、requiredCapabilities、optionalCapabilities、contributions。扩展ID与贡献ID命名空间化；重复ID明确拒绝，不能靠任意 priority 覆盖已有入口；顺序由市场限定的位置及排序字段决定。

`register(ownerScope, definition)` 整组验证后登记，返回成功句柄或结构化拒绝；失败撤销已登记部分。菜单与对应页一起校验，不能出现死链接。`dispose()` 可重复调用且清除贡献、受管订阅与异步请求。ownerScope 绑定实际调用生命周期，不把声明里的 author/owner 字符串当认证。

建议市场提供版本化 Client 服务 `eacMarketExtensions`。独立插件用官方 Cordis 依赖注入等待服务就绪，并以 `ctx.effect` 绑定销毁；包名的 metadata inject 不能冒充运行顺序保障。市场停用、槽位声明撤销和重建、先装扩展后装市场、热重载分别测试。合作插件无关的自身功能，不应因可选市场接入缺失而无法加载；必要时把接入做成独立可等待的 Client contribution。

SDK 的组件/回调类型与 Host/Client 之间的 JSON Remote 类型分开。公开独立扩展 type-only 导出与最小 runtime helper，声明 peer 依赖并复用宿主 React，避免二份 React 或运行时导入市场内部文件。导出名称先由主控冻结、测试真实安装解析后写入作者指南。

### 有限上下文与真实信任边界

扩展拿必要的只读副本：市场/宿主版本、当前插件摘要、明确需要的脱敏任务状态或草稿片段、能力表、取消信号。允许 `openDetail`、`openOwnPage`、`requestInstallReview`、`previewDraftChange` 等受控请求；安装仍回到核心预检确认。不要传全部 ctx/Remote、状态 setter、密钥、会话、绝对路径、`confirmed` 或直接 startTask。

菜单/动作采用声明式描述，二级页和补充区可用受审 React 组件：前者易统一，后者方便合作作者设计。每条渲染有错误边界，事件/Promise 异常显式捕获；受管请求超时并忽略旧实例回包；样式限定命名空间，不对宿主根选择器写全局样式。

**这不是安全沙箱。**同一 JavaScript 环境内的普通 DSH 插件仍可能自行访问宿主服务、改 DOM 或阻塞线程；React 错误边界不能终止死循环，也不能证明能阻止恶意插件绕过合同。首版只对受审团队/合作插件承诺合同内兼容与故障处理；未来如需执行不可信代码，应另立受限 iframe/worker/进程方案及通信权限验收，不用当前方案作安全宣传。

## 7. 首页内容更新与未来打包

首页核心由团队维护，小而清晰：搜索入口、少量真实精选、用途、规则发现、可用组合。每个人工精选记录推荐理由、适用版本与责任人；过期或撤回不继续推荐。自动排序用真实兼容范围、用途和可核验发布时间；相同排名用稳定ID保持顺序。介绍更新时间不能冒充程序更新。无内容不造评分/下载量/合作证明。

后续新专题优先通过 Presentation/Recommendation 配置；真正新功能才用扩展模块。基础全家桶打包另维护精确组合清单，不写进首页组件或安装器分支；自动预装后续复用同一预检/执行/真实回执机制及独立 bootstrap，不把市场每次打开等同重新装套餐。

现有 EAC 插件功能只是候选池。每个迁移条目检查标准官方接口、许可、第三方依赖、配置变化和使用说明，再上架；不能复制旧 `window.dshDesktop` 插件后标为官方兼容。内置、推荐、外部的分发意图与验证程度分别表示。
