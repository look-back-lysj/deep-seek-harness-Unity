# 下一阶段实施计划：先修可靠安装，再打通生态接入

版本：review-next v1，2026-09-28。**这是待执行计划，不是功能完成报告。** 本轮真实发现见 [独立复查](reviews/2026-09-28-independent-review.md)，作者／扩展接口见 [生态接口](ECOSYSTEM-INTERFACES.md)，派工提示词见 [多智能体接力](handoff/NEXT-AGENT-PLAYBOOK.md)。

## 1. 给用户先看的结论

下一轮不需要重写市场。保留官方 DSH 安装器和现有页面，先把「点安装→确认内容→下载同一份包→官方安装→页面反映真实结果」修成闭环。然后让合作作者能交付资料、发行包或授权源码，团队能审核生成目录；最后把市场页面的扩展位置开放给团队模块和独立插件。

这三件事分别验收。只有页面好看、测试绿色、包能加载，都不足以证明商城完整可用。首页本轮只整理结构与扩展接缝，具体推荐专题和全家桶名单可继续由团队补充。

## 2. 已定事项与建议默认

已由用户决定：三个主页面；混合商城；人工精选和规则排序并存；安装套餐列出版本调整后统一确认；部分失败保留成功；未验证可明确试装且不绕硬限制；基础内容后续打包；作者本地编辑／导出先行；在线作者平台及所有 Star 后置；DSH 默认模型无工具分析、市场执行确认后的有限动作；卸载／降级再次确认。

本轮新增决定：**作者发行包优先，特殊插件也支持团队构建；团队内置模块与独立合作插件两种扩展都要。** 不能在实施中默默删掉其中一种。

下表是计划采用的技术建议，不冒充用户逐项批准；它们不扩大权限或删减已定能力。若用户接受本计划并要求实施，可采用推荐默认。会改变产品范围、公共协议、许可证或远端发布权限的变化，先给事实和选项。

| 技术问题（通俗解释） | 推荐默认及好处 | 备选与代价 |
| --- | --- | --- |
| 怎样避免两个操作同时改同一环境 | 继续用现有执行器，所有市场管理动作经过一处协调；执行占用与短时保存锁分开，取消可及时登记。改动集中 | 重建持久命令队列，扩展性更好，但迁移与故障面更大；当前不因审计重写全部核心 |
| 任务怎样抗中断保存 | 保留 JSON，增加操作提交记录、可重建索引和恢复检查。无新增数据库依赖 | 换 SQLite 事务，关联保存清楚，但增加依赖、迁移与打包验证；待 JSON 方案确实不能满足规模再比较 |
| AI 一次建议多少动作 | 每个可执行提案先严格一项，保留用户选定的全部动作种类。清单与实际执行一致，二次确认好验证 | 多项编排可少点几次，但须完整依赖、确认、取消及部分结果协议；不能仍只取 actions[0] |
| 独立插件怎样扩展市场 | 一个注册合同＋内置／官方插件两层接入，核心动作由市场渲染和确认；既能扩展也能维护 | 任意网页脚本/直接改 DOM 更自由，但不稳定且无法执行边界；不作为本轮实现 |
| 正式内容放哪里 | 团队审查的静态目录＋GitHub/Gitee 不可变发行文件，自动校验后生成索引，开发仓与内容源分开 | 作者在线平台自动发布更省人工，但账号、认领、滥用治理尚未设计，已明确后置 |
| 普通官方插件没有社区 Manifest | 使用市场私有 official-bundle 元数据分支，保留原声明；真正遵循 dsh-std 的对象另按公共协议校验 | 强制每个作者补社区 Manifest 看似统一，却改变已定标准 DSH 兼容范围，不能默认采用 |

## 3. 阶段与依赖

工期不写虚假的小时保证，以每阶段可检查的成果推进。I 系列修复和 E 系列新能力分开记录；若外部正式发行资料缺失，仍完成工程接口与测试包，线上验收如实标 blocked。

| 阶段 | 主责任与工作 | 输入／产物 | 放行标准 |
| --- | --- | --- | --- |
| G0 冻结事实与接口 | 主控核对当前工作树、远端、官方包及协议；读 REV、旧 AUD/ACC；登记文件 owner | `baseline.json`、契约修订说明、每条验收 owner；保留未知修改 | 构建命令、目标环境、协议来源可复现；没有拿旧报告代替当前状态 |
| G1 修安装基础 | 安装 Worker 修 REV-01–07、15；主控修 Host 接线，内容 Worker 给冻结来源与证据接口 | 不可变计划、来源证明、取消控制、恢复记录、意图防重、真实重启屏障 | 每个缺陷先复现再回归；使用生产锁／持久层；未知库存和未知回执不写入 |
| G2 修跨层产品链 | UI Worker 修 REV-10/13/14；内容 Worker 修 REV-11/12；主控连接 ordinary enable/remove 与刷新 | 同页库存同步、真实状态、预检确认、作者往返、受控目录 | 无假成功；普通新装／更新／启停／卸载／作者路径分别走通；首轮真实 Desktop 复查 |

| G5 双扩展与首页接缝 | 扩展 Worker 实现注册表／两适配层；UI Worker 挂五类槽位；主控冻结 SDK 导出 | 同一合同、内置样例、独立标准 DSH 测试插件、维护文档 | 不重打市场也可安装独立扩展，启停／重载／失败／清理通过；三个主导航保持不变 |
| G6 最终交付 | 主控停止并行改动→构建→打包→QA 独占 Desktop；Reviewer 独立审查 | 最终 tgz/SHA/源码提交、完整结果表、未完成条件、README 与升级指南 | 实际安装的就是最终包；所有强制测试逐项登记；仅对确实通过的部分用 verified |

G0 之后，内容资料／UI局部／安装核心可以按不重叠文件并行。G3 的严格解析和诊断采集可提前做，执行依赖 G1/G2。G4 模板、G5 合同与纯注册表可并行；Host 和主页面接线按 owner 串行。构建、打包和真实 Desktop 永远由主控统一排程。

## 4. 第一部分：修复现阶段功能

### 4.1 预检与确认必须真实有效

点击「安装」即自动发起**只读预检**，不要求新手再点「生成正式方案」。预检完成展示友好名称、确切新旧版本、保留／安装／升级／降级、启用选择、脚本与重启要求、需要试装的对象。首次打开不是同意。

Host 创建的计划保存环境身份、宿主能力、安装意图、选择条目、旧状态证据、目标摘要、来源清单摘要、风险确认摘要及到期时间。Client 只提交计划引用与明确用户动作，不能用新目录重拼执行目标。试装选项变化重新生成预检；旧确认作废。未知与 unverified 均按真实验证状态处理；hard-incompatible 一直拒绝。

确认不能只有传 `confirmed:true` 就视为所有条件满足。Host 核对挑战（即本次待确认内容的唯一凭证）、范围、有效期、实际对象和使用次数；记录真实前端确认流程。下一轮先核查官方 Remote 是否提供可靠调用者身份，不能凭空发明认证接口。同一进程内已获执行权的恶意插件不能靠一个布尔值或 JS 对象彻底隔离，详见扩展信任边界。

同一进行中的操作重复点击、双标签分别预检、AI 重复确认，应返回同一活动任务或准确的冲突提示；已经失败且结果核定的新尝试允许执行，并保存 `retryOfTaskId`。`proposalId`、`planId`、`taskId`、`attemptId`、安装意图摘要各司其职，不串用。

### 4.2 执行、取消与恢复

统一市场协调覆盖安装、更新、启停、卸载、脚本批准、恢复继续及 AI 派生动作。始终调用官方 manager；不手写用户 patch、不绕官方包管理器、不嵌套持有它的同一文件锁。

推荐锁模型：执行占用表示「这个 profile 正在进行一项市场写入」；记录锁只覆盖短时保存。取消意图可独立落盘。**进入待核对本身不能解除环境写入阻断**：必须证明旧写入已经停止、共享状态完成核对，才允许下一个写入者。可以保留执行占用，也可释放底层锁但保留可恢复的持久阻断标记；Host 中断后仍须重建这一阻断。AbortSignal 传到下载；每次下一组件写前重读取消状态；不能把「已请求取消」显示成「全部撤销」。

```mermaid
flowchart LR
  A[点击安装] --> B[只读预检]
  B --> C[用户核对并确认]
  C --> D[登记任务与执行占用]
  D --> E[获取并校验同一制品]
  E --> F[再次核对当前状态与取消]
  F --> G[官方安装器]
  G --> H[持久记录回执并读取库存]
  H --> I[完成／部分完成／待重启／待核对]
```

下载结束、脚本批准返回、重启继续之后，**每次**写入前核对包版本、启停、来源归属、宿主能力和关键库存可读性。固定顶层 tgz 摘要不等于锁定所有传递依赖；依赖缺失和脚本许可仍交官方处理。

边界必须诚实：市场自有锁不能阻止官方页面或外部工具同时改 profile。若官方 API 不支持原子比较旧版本再写入，最终一次读与官方写之间仍存在小窗口；应尽量缩短、核验官方忙状态与写后结果，发现冲突记待核对。**不能宣称新增市场锁就获得跨所有工具的原子事务。** 不通过私改官方源码弥补这一限制。

恢复时保存「准备发起、已发起、收到回执、核验完成」的事实，区分确切已完成与结果未知。官方 `waitForInstall=null` 只能说明不在活动表中，不能当作成功、取消或未执行。旧调用未知先读取官方进程记录、原请求事实、磁盘及库存；可证明目标状态则结算，证据冲突／缺失保留待核对；不能用旧 requestId 自动再装一次。

JSON 保存采用原子文件＋带版本/校验的操作提交记录；索引作为可重建派生数据。单元测试在摘要、事件、索引每个写点中断后重建服务；孤立/损坏记录必须可发现且不当空。旧任务迁移先备份市场自有记录、验证再切换；遇到旧活动任务的未知状态不自动清空或重放。

### 4.3 来源、重启与普通管理

市场安装回执绑定 package/version/digest 和缓存引用。启动后与实际 profile 依赖引用及文件核对，才恢复市场归属；用户自己换成 link/fork 或修改字节会失去自动覆盖资格。缓存被 profile `file:` 依赖引用期间不能清理；只在证明无活跃任务、库存和历史恢复需要后回收。

磁盘已是新版本、配置已启用、运行成员实际使用新版本是三件事。官方 `restart-required` 不能因仍有旧 active 成员被抹掉。宿主启动身份优先使用真实可证明的官方信息；没有相应 API 时，验证所在 Host 进程是否与插件服务重载独立，再决定能提供哪些证据。无法证明目标已运行时保持等待，不拿包数、当前时间或市场服务初始化冒充宿主重启。

普通卸载保留用户之前选择的保守数据行为，不额外清理未知目录；第三方卸载自身的影响不能保证。展示实际受影响成员、反向依赖及配置行为；证据不足只阻断相关危险动作，不永久锁住全部正常安装。市场自身停用／卸载交由官方管理页，避免执行器在自己的操作中消失。

### 4.4 UI 与首页规格

先读取既有界面与产品规则并调用 `impeccable` 的 Operate/Read 流程。沿官方主题与组件，先修使用路径；不引入大型动画库、视频背景或外部字体依赖。必要的 120–180ms opacity/transform 过渡可作为建议，支持减少动态效果；不能靠动画掩盖响应慢。

| 页面／部位 | 下一轮具体要求 |
| --- | --- |
| 发现 | 紧凑介绍与直接搜索入口；真实团队精选附一句推荐理由；用途分类和规则发现；可选套餐区；五类槽位中的首页补充区放核心内容之后。没有数据隐藏空分区或给一条短说明，不铺多个大空框 |
| 全部插件 | 搜索、用途、兼容／版本筛选和明确排序；保留返回前条件及滚动；无目录、搜索无结果、网络失败用不同空态；用户排序不被推荐强制覆盖 |
| 详情 | 固定真实名称、作者、版本、状态和主要操作；正文／截图自由展示但先净化；「来源与兼容详情」折叠；作者正文不能伪造验证或安装按钮 |
| 安装预检 | 一次自动预检→一次明确确认；未验证额外勾选，升级/降级差异清楚；只显示本次对象。A 的迟到响应不关闭 B；忙中可关闭页面但不伪取消任务 |
| 任务 | 一张卡一个真实任务及绑定的 AI 提案；阶段/已完成数量代替虚假下载百分比；保留成功项；待重启、取消中、结果未知给不同入口；内部枚举只放诊断详情 |
| 我的插件 | 先显示可用功能与真实中文名，系统组件折叠；未知原始组件放可展开诊断，不无限占主列表。任务终态、启停后同页同步；已停用不等于未知；实际错误不能隐藏 |
| 作者工具 | 草稿列表／重开、脏状态提示、冲突提示、README预览覆盖、媒体、真正资料 ZIP；保留已成功的首次保存 |
| 设置与帮助 | 来源状态、最近成功刷新时间和失败原因；不显示保存即联网成功。帮助是次级入口，首屏不反复堆工程解释 |

把 `MarketPage.tsx` 按 view/data-controller/hooks 拆小，提取目的为职责与测试，不是重写视觉。状态控制器按 environment 和代次管理；有界串行同步、旧响应拒绝、失焦可降频、终态刷新库存。通过已核实事件或定时 listTasks/回到面板补偿发现其他标签任务，不能只轮询自己已知的任务。

性能验收：正常桌面与约 480px 内容区、深浅色、键盘和焦点恢复；长目录测试搜索与滚动，测量再决定虚拟列表；关闭面板不累积定时器／监听器。一次成组检查、一批修正、一次确认，不无限为微小视觉差反复构建。未作性能测量不能声称 60fps。

### 4.5 AI 与作者闭环

AI 继续遵守 [操作守则](AI-ASSIST-RULES.md)，先修 REV-08/09 再开放。诊断只收本任务所需官方错误、阶段、版本、来源尝试、库存异常及限长日志片段；删除 token、cookies、个人路径、会话与无关文件。让用户可看将发送的摘要；没有错误材料就说明不足，不让模型凭空归因。

建议与执行分离：默认模型无工具调用→严格解析→后台补全／验证影响→持久提案→普通确认→危险动作独立再次确认→进入同一执行器。模型不知道密钥、不传工具、不允许任意 URL/命令/路径或自己提供 confirmed。提案到期、目标漂移、模型取消、缺 finish、额外字段或多动作超首版范围都拒绝执行，并保留手动排错入口。

AI 成功与否不影响已经确认的普通安装；无可用模型时正常市场仍可用。真实模型测试必须使用专用可授权配置，不复制真实用户密钥到仓库/测试目录；未具备条件则真实模型项 partial，不能从假模型推断通过。

作者链使用现有模块，修接线优先：新建不伪造覆盖对象；覆盖带 expectedRevision；导出无新来源参数时保留草稿已有 provenance；有新参数明确是合并还是替换，不能 `{}` 清空。图片通过受控媒体解析，不允许任意 file URL、外部跟踪图默认请求或执行 HTML。资料 ZIP 和可执行插件 tgz 用不同格式、不同导入入口、不同提示。

## 5. 第二部分：为上架、安装与扩展准备完整接口

详细字段、模板、生命周期、五槽位与两适配层以 [ECOSYSTEM-INTERFACES.md](ECOSYSTEM-INTERFACES.md) 为准。最少交付以下实物，不能只留 TODO：

1. 作者资料模板、发行包验收清单、授权源码构建说明；两条路线各一套无害演示资料。
2. 能读取并校验模板的生成器，产出真实目录；正式地址缺失时测试源明确标 test，不进入生产目录。
3. 官网标准 bundle 与真实 dsh-std Manifest 两种元数据适配；公共 Mojobox schema 原样遵守，不加私有字段。
4. GitHub/Gitee 制品镜像核验、目录缓存、撤回记录和一致性说明；优先级换源限同版本同摘要，不能拉 main 源码直接当安装包。

## 7. 交付与升级规则

每模块注释解释其职责、状态边界、为什么不能绕过官方服务及如何清理；不要求给每一行复述语法。每个新增目录有 README，总目录链接到真实文件；升级指南包含 schema迁移、官方版本验证、目录生成、作者发布与扩展移除。
