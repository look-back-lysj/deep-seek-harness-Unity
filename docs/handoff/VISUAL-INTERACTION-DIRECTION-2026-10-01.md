# EAC Market 视觉与交互方向合同

日期：2026-10-01
状态：Phase 1–5 已实现第一批代码；本文件仍是 Client 视觉重构的唯一设计方向，Phase 6 真实宿主验收尚未完成。

## 1. Design Read

Reading this as: **嵌入官方 DSH 窄面板的插件市场重构**，服务新手用户、插件作者和维护者，采用安静的编辑型工具语言，靠清晰层级、真实状态和内容节奏建立高级感，而不是靠装饰堆叠。

设计参数：

- `DESIGN_VARIANCE = 6`：有编辑感的比例变化，但不牺牲目录扫描和窄面板兼容。
- `MOTION_INTENSITY = 4`：动效只解释层级、反馈和状态变化。
- `VISUAL_DENSITY = 4`：发现页偏展示，全部插件偏工具，任务/作者工具偏工作台。

## 2. 现有界面为什么显得旧

当前代码已经解决了很多行为问题，但视觉骨架仍然是早期的“顶栏 + 大量同质卡片 + 普通边框 + 全局淡入”：

1. 首推海报虽然有尺寸和降级，但仍像一张放大的普通卡片，缺少独立舞台的视觉焦点。
2. 发现页的所有区块使用相近的标题、边框和间距，用户看不出主次节奏。
3. 目录卡、皮肤卡、高分卡和详情信息重复使用同一层 surface，内容类型没有自己的视觉语法。
4. 顶栏、页面标题、区块标题和动作按钮都在争夺注意力，首推内容没有形成明确的阅读起点。
5. 视觉反馈主要是颜色变化、阴影和统一淡入，无法解释“我刚刚做了什么、状态改变在哪里”。
6. 任务和作者工具信息准确，但仍偏表单堆叠，缺少工作台的固定操作区、进度关系和收尾感。
7. 深色模式只是颜色反转，缺少真正的层级、边缘和焦点处理；窄面板则依靠挤压换行，缺少针对性布局。

下一轮会先改这些结构问题，再处理微动效。

## 2.5 方向选择与取舍

| 方向 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| A. Quiet Editorial Utility | 视觉高级、信息层级清楚、能沿用 DSH token、窄面板和 forced-colors 兼容性最好 | 需要重新做比例、留白和内容节奏，第一眼不会靠炫技取胜 | **采用** |
| B. Dark Media-first | 海报和皮肤展示更有冲击力，适合图片内容丰富的目录 | 图片缺失时容易变空；深色对比、打印、forced-colors 和低端设备风险更高 | 作为局部主题参考，不做全局基线 |
| C. Swiss Catalog Grid | 目录扫描、排序和比较最强，工程感明确 | 对新手偏冷，发现页容易退化成表格，不能承载首推叙事 | 只用于全部插件的密度和对齐 |
| D. Glass / 3D Showcase | 视觉变化最大，容易做出短期“高级”印象 | 依赖 blur、图片和 GPU；窄面板、旧浏览器、forced-colors 和 reduced-motion 退化明显 | 不采用 |

采用 A 不是继续堆装饰，而是把 B 的媒体舞台、C 的目录秩序和 D 的少量空间感拆成可降级的局部规则。
## 3. 视觉世界：Quiet Editorial Utility

### 3.1 颜色

- 页面底色：使用官方 DSH background token，浅色保持温暖的近白，深色保持有层次的近黑。
- 内容 surface：最多三层；内容底、提升层、浮层。普通卡片不再单独堆厚阴影。
- 主强调色：只使用官方 business/link token，作为主操作、当前导航、进度和焦点的统一线索。
- 状态色：success / warning / danger / info 只用于真实状态，不作为装饰色。
- 图片海报：媒体自身承担视觉主色；无图降级使用低对比的纸张纹理和文字，不用高饱和渐变抢焦点。
- 强制颜色模式：所有信息必须仍由文字、边框、位置和原生控件表达，不能只靠颜色。

### 3.2 字体与文字

- 沿用官方 DSH 字体变量和系统 fallback，不引入不确定的外部字体下载。
- 页面标题控制在 30–42px；区块标题 18–22px；正文 14–15px；元信息 12–13px。
- 标题使用稳定的字重层级和 `text-wrap: balance` 增强，旧浏览器以普通换行降级。
- 长中文、英文包名、版本号和 URL 必须允许断行；任何标题不以固定行数截断重要信息。
- 文案先说动作和结果，再说解释；避免“处理中”这种没有下一步的空状态。

### 3.3 表面、边缘和空间

- 通过留白、细分隔线和对齐建立层级；不把每一段内容都包成圆角卡片。
- 普通内容使用 1px hairline border 和轻微背景差异；阴影只保留给 Modal、菜单、任务浮层等真正脱离页面的对象。
- 圆角只有三档：控件、内容块、浮层。不要让每个元素都拥有不同圆角。
- 页面主内容采用 8px 基础节奏，区块之间使用 32–48px 的大间距；标题上方空间大于标题下方空间。
- 宽面板用固定内容轨道和可控最大宽度；窄面板切换为单列，避免三列压缩成不可读的卡片。

## 4. 页面布局合同

### 4.1 全局壳层

顶栏分为三层职责：品牌、主导航、次级动作。主导航只保留“发现 / 全部插件 / 我的插件”；任务、帮助、设置、作者工具进入次级动作区。

当前页使用细线和轻微背景变化标识，不使用厚重胶囊。内容区和顶栏形成明确的控制层/内容层关系，滚动时不遮住首推或标题。

### 4.2 发现页

发现页采用“一个舞台 + 三种内容带”的节奏：

1. 页面标题区：一句清楚的价值说明，右侧只放两个最高优先级动作：“搜索全部插件”和“使用帮助”。
2. 首推舞台：左侧媒体/文字海报，右侧推荐理由、版本和主要动作。首推是唯一允许明显视觉重量的区域。
3. 推荐皮肤：横向内容带，展示皮肤的视觉缩略、作者和当前可用状态；没有真实皮肤数据时整个区块隐藏。
4. 高分插件 / 高分 Skill：使用排名式列表或不等宽内容块，不再做四张完全相同的卡片；没有真实评分时隐藏。
5. 规则发现：紧凑的用途筛选和目录列表，明确“浏览全部插件”是唯一进入完整目录的动作。

首推轮播规则：

- 只在内容多于一项时出现轮播控制。
- 鼠标悬停、键盘焦点、页面隐藏时暂停自动轮换。
- 每次切换只变更舞台内部媒体和文案，不重置页面滚动，不把用户跳到全部插件。
- `prefers-reduced-motion` 时只切换内容，不做位移和缩放。

### 4.3 全部插件

全部插件是工具页，不继续沿用发现页的编辑密度：

- 顶部是搜索、结果数量、当前筛选和排序；筛选状态必须在视线内可见。
- 高级筛选在宽面板中采用工具栏展开，在窄面板中采用可关闭的筛选面板；关闭后保留已应用条件。
- 目录结果使用两列内容网格或单列密度列表，卡片不再嵌套卡片。
- 每项固定显示名称、作者、简介、版本/兼容、验证状态和一个主要动作；次要信息放进详情。
- 清空筛选、无结果、目录刷新失败和状态未知都使用同一套反馈位置，避免消息在页面顶部跳来跳去。

### 4.4 详情页

宽面板使用内容主列 + 固定动作/事实栏；窄面板把动作栏移到标题和简介之后。主要动作始终在同一个相对位置：查看安装方案、管理、打开官方插件页或明确禁用原因。

截图、作者介绍、来源与兼容信息按渐进披露组织；缺失资料用空状态解释缺什么，不用大块空白撑版面。

### 4.5 任务面板

任务面板是工作反馈层，不是普通 Modal 内容堆：

- 顶部显示任务标题、当前状态和关闭按钮。
- 中部显示下一步和逐项结果，成功/失败/未知关系清楚。
- 底部保留当前可执行动作；提交中不能误关闭，关闭后任务仍可从任务入口恢复。
- AI 分析、脚本授权、重启核对和再次确认只在需要时出现，不把所有按钮同时摆出来。

### 4.6 皮肤中心与作者工具

皮肤中心的第一视觉是“当前外观 + 管理器状态”，皮肤列表是第二层。切换失败、疑似残留和结果未确认必须在当前皮肤项附近显示恢复动作。

作者工具使用工作台布局：宽面板左侧草稿和编辑，右侧阅读预览；窄面板按“保存状态 → 编辑 → 预览 → 导出”顺序堆叠。保存状态固定在编辑区上方，脏状态和后台 revision 不能被埋在普通提示里。

## 5. 交互状态合同

### 5.1 页面导航

- 页面切换只改变 Client 内部状态，不使用 DSH 私有路由。
- 进入详情、皮肤、作者、帮助和设置前保存 `NavigationSnapshot`。
- 返回时恢复来源页、筛选、排序、分页、滚动位置和可用焦点；原节点消失时回退到页面标题。
- 连续点击只提交最后一次导航意图；旧请求不能覆盖新页面。

### 5.2 搜索与筛选

- 搜索是本地快速反馈，不触发远程请求，不改变来源上下文。
- 筛选值分为 draft 和 applied：宽面板可在控件变更后即时应用，窄面板点击“应用筛选”后提交，避免小屏每次选择都跳动。
- 应用筛选时保留页面位置；结果变化只对结果区做短暂反馈，不让整个页面重新进入。
- 清空筛选是一个明确动作，清除来源条件、排序和分页，并把焦点返回搜索框。

### 5.3 安装与管理

- 卡片主动作统一为“查看安装方案”或“管理”，不在不同页面使用“安装 / 立即安装 / 确认安装”混乱表达。
- 预检、确认、提交和后台任务是四个可识别阶段；每阶段只显示当前需要的动作。
- `unknown` 永远进入“重新核对”，不提供看起来像可以安全重放的成功按钮。
- 失败反馈靠近触发动作；全局顶部只保留环境级同步失败。

### 5.4 任务与 AI

- 任务关闭不等于取消；关闭后保留真实任务。
- 取消、授权、重启核对、再次确认都使用明确的动作和后端状态回读。
- AI 只提供建议和事实；第一次确认不写入，危险动作由后端 challenge 决定第二次确认。
- 取消二次确认后清理旧 challenge、提案和幂等键。

### 5.5 脏状态和恢复

- 作者草稿脏状态离开时给出“继续编辑 / 离开但保留本次编辑”两种明确选择。
- 保存、导入、上传和导出失败后原地重试，不清空表单，不伪造已保存。
- 皮肤切换失败后不自动再次切换；先核对当前外观，再允许重试。

## 6. 动效合同

动效只承担四种职责：层级、状态变化、用户反馈、叙事顺序。每个动效都必须能说明它传达了什么。

| 场景 | 动效 | 时长 | 说明 |
| --- | --- | --- | --- |
| 主视图切换 | 透明度 + 4px 位移 | 180ms | 只作用内容区，顶栏不动 |
| 首推内容切换 | 媒体淡出/淡入 + 文案交叉 | 220–260ms | 不改变页面滚动 |
| 结果区更新 | 轻微透明度变化 | 160ms | 不逐张卡片重复入场 |
| 菜单/浮层 | opacity + translateY(4px) | 140ms | 可立即打断 |
| 成功/失败反馈 | 状态色和图标短反馈 | 120–180ms | 文字是主要信息 |
| 任务状态更新 | 只强调变化的行 | 160ms | 不制造假进度 |

禁止：`transition: all`、无限 shimmer、自动缩放卡片、连续 marquee、用动画代替文字、必须等动画完成才能操作。

动画必须支持 `prefers-reduced-motion`，并允许用户立即取消或继续操作。短、精确、与动作直接相关的反馈更容易让人理解，也更不打扰当前任务。

## 7. 兼容性合同

- 先提供普通 CSS 布局，再用 `@supports` 和容器查询增强；不依赖 View Transitions、backdrop-filter 或 JS 测量才能工作。
- 所有媒体指定宽高比、`object-fit` 和失败降级；网络图片失败不能改变布局高度。
- 120%–200% 缩放和大字号时，横向相邻内容可以堆叠，不能裁切正文。
- 所有主要按钮、标签、搜索框和焦点目标保留充足间距；触控/高 DPI 预览目标不小于 44px。
- 窄面板使用单列安全布局，长中文、英文包名和 URL 可以断行；不使用固定高度裁切内容。
- forced-colors 下去掉渐变和阴影依赖，保留边框、文字和原生焦点。
- 深色模式不是简单反转：页面底、内容层、浮层、边框和状态色各有层级。

响应式布局必须根据窗口变化保持熟悉的关系、对齐和阅读顺序；重要内容优先放在顶部和主阅读方向上，相关内容用空间、对齐和分组表达。

## 8. 后端对接边界

本方案不要求修改 Core、Remote 或安装协议。Client 继续消费：

- `CatalogSnapshot.discovery`：首推、皮肤、高分和海报可选投影；缺失就隐藏/降级。
- `PluginActionResult`：启用、停用、卸载的真实状态和错误。
- `TaskState`：任务阶段、逐项结果、授权、重启、unknown 和事件。
- `AuthorDraft` / transfer 结果：revision、媒体和导出状态。
- Skin runtime bridge：当前皮肤、切换结果、回退和疑似残留。

如果实现视觉方案必须新增字段，优先做可选展示字段，并先写合同、兼容策略和测试；不能把纯视觉需求变成新的必需后端能力。

## 9. 实施顺序

### Phase 0：设计冻结

- 记录本合同和当前基线截图。
- 确认 token、字体层级、surface 层级、响应式断点和动作文案。

### Phase 1：视觉骨架

- 重写页面壳、顶栏、内容轨道、surface 和类型层级。
- 去除同质卡片堆叠，建立发现页/目录页/工作台三种密度。

### Phase 2：发现页

- 首推独立舞台、推荐皮肤内容带、高分排名区和规则发现列表。
- 实现无图、无数据、图片失败、暗色和窄面板降级。

### Phase 3：目录与详情

- 目录工具栏、结果区、筛选面板、详情动作栏和渐进披露。
- 保持 NavigationSnapshot 和现有 Remote 不变。

### Phase 4：任务、皮肤、作者工具

- 任务状态轨道、皮肤当前外观、作者保存工作台和脏状态反馈。
- 统一动作状态组件的视觉表达。

### Phase 5：动效与兼容性

- 只加入本合同规定的动效。
- 验证 reduced-motion、forced-colors、窄面板、大字号和网络图片失败。

### Phase 6：验收

- `pnpm typecheck`
- Client 定向测试
- `node tests/client/browser-check.mjs`
- `impeccable detect --json packages/market/src/client`
- 真实 DSH Desktop 的主题、读屏、缩放、forced-colors、Modal 覆盖和官方管理器验收

## 10. 完成标准

- 用户进入发现页后 3 秒内知道推荐内容、完整目录入口和当前主要动作。
- 发现页与全部插件页在密度和任务目的上明显不同。
- 任一异步动作都有当前阶段、真实结果和下一步；unknown 不会被误读为成功。
- 任何页面在 480px、120%–200% 缩放、深色、forced-colors 和 reduced-motion 下都仍可操作。
- 视觉变化来自层级、比例、对齐、内容节奏和有理由的动效，而不是卡片、渐变和阴影数量。
- Client 仍只消费既有 Core / Remote 接口，没有后端合同漂移。
