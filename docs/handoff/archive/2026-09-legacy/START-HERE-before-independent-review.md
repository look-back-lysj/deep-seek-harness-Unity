## 8. 命令、打包与测试环境

当前存在的命令入口如下；**先修 S0，再在新检出／隔离目录验证可重建**：

```powershell
Set-Location -LiteralPath 'D:\eac-market' -ErrorAction Stop
node --version
if ($LASTEXITCODE -ne 0) { throw 'Node 检查失败，停止后续步骤' }
git status --short --branch
if ($LASTEXITCODE -ne 0) { throw 'Git 状态检查失败，停止后续步骤' }
node scripts/build.mjs
if ($LASTEXITCODE -ne 0) { throw '构建失败，停止后续检查与打包' }
pnpm.cmd check
if ($LASTEXITCODE -ne 0) { throw '完整检查失败，停止交付' }
pnpm.cmd test:catalog
if ($LASTEXITCODE -ne 0) { throw '目录专项检查失败，停止交付' }
```

`check` 当前先 typecheck 后 build，干净目录会先缺生成的 Remote；不要把已有 lib 目录掩盖的成功当可重建。`build.mjs` 会清包内 lib，故不能与其他 worker 的构建／正在使用产物的测试同时运行。

安装包始终从包目录打出，并用**新的验证目录**保存，避免覆盖旧审查包：

```powershell
# runId 由主控为本批次确定。目录必须位于专用验证根，不能指向用户profile。
$marketVerifyRun = 'D:\eac-market-verify\<本批次runId>'
New-Item -ItemType Directory -Force -Path $marketVerifyRun -ErrorAction Stop | Out-Null
Push-Location -LiteralPath 'D:\eac-market\packages\market' -ErrorAction Stop
try {
  npm.cmd pack --dry-run --json
  if ($LASTEXITCODE -ne 0) { throw '打包清单检查失败，不生成交付包' }
  npm.cmd pack --pack-destination $marketVerifyRun
  if ($LASTEXITCODE -ne 0) { throw '正式打包失败，不能记录为已交付' }
} finally {
  Pop-Location
}
```

上面的 `<本批次runId>` 是必须替换的说明标记，不可原样运行。打包后读取真实输出文件名并计算 SHA256，不预设下一版本名。当前 `test:pack` 主要查文件、exports 路径和生成文本存在，必须补实际运行 schema／导出解析与官方加载测试；不能沿用其输出中的“strict”字样作为完整证明。

PowerShell 的 `try/finally` 只保证返回目录，不会自动把原生命令的非零退出码变成异常。保留上面的 `$LASTEXITCODE` 检查；前一步失败时不得继续打包或记录成功。

环境规则：

- Windows PowerShell；路径使用 LiteralPath 或安全引号；不要混 Bash、不要把文字拼成会执行的 shell 替换。
- 本轮工具环境是 `danger-full-access + approval never`，不支持 `sandbox_permissions`。下一轮按实际工具策略走，不照抄旧备忘中“联网必须提权”的参数。
- 下载使用 Motrix；地址和本机凭据从当前用户全局说明读取，**不把 RPC secret 写进仓库、脚本、日志或交接**。大文件放 D 盘。

- `BlockAssembler.finish` 缺结束数据时默认 stop；必须检查实际收到的 `finish` 事件和 `reason.kind`，不能直接信默认值。
- 先补具体错误和日志引用；现有 `diagnosticsExport()` 分类名不是可供诊断的材料。
- 用户确认来自市场 UI 及 Host 记录，绑定本次诊断、环境、方案、期限和影响范围。卸载／降级再次确认；模型不能伪造同意。
- 卸载影响契约须包含精确包版本、受影响成员、反向依赖、配置／数据行为及证据来源；降级另绑定新旧版本组合和数据兼容依据。`removable=true` 不是数据安全证明，套餐依赖图也不是整个已装环境的完整依赖图。
- 缺关键证据只阻止对应操作；不能把全部按钮永久禁用后宣称支持。用可证明无状态的隔离插件验卸载／降级成功，用状态迁移不兼容及依赖未知样本验拒绝。
- 已确认任务不依赖模型一直在线。模型掉线不重装、不自动回滚；官方状态未知时先核对。

## 13. 后台任务的统一操作表

推荐沿用现有读取接口做有界、串行同步，先不为此新增复杂事件系统。Host 持有任务；页面卸载或模型对话关闭不取消安装。页面重开、恢复连接、重新获得焦点时同步任务列表和库存；打开期间也能发现其他标签或 AI 入口创建的新任务，不能只轮询当前页面已知的几个 taskId。

| 当前事实 | 应显示／允许的动作 | 不允许 |
| --- | --- | --- |
| 排队、下载、安装、应用中 | 真实进度；按官方阶段允许请求取消 | 新建等价任务抢写 |
| 待脚本许可 | 显示精确清单与持久影响，批准后继续原任务 | 新建另一个安装任务或泛化批准所有脚本 |
| 等待重启／继续 | 核对新运行实例及剩余清单，通过原任务继续入口 | 把已配置启用当已运行；重新start覆盖历史 |
| 明确失败／明确取消 | 核对实际已落地结果，为允许的剩余动作生成关联旧任务的新方案 | 重装成功项；清记录解除冲突 |
| 取消中／结果未知／Host中断 | 正在核对、查看原因；确认旧写入停止后再处理 | 直接重试、自动重放或宣称已撤销 |
| 完成／部分完成 | 分项事实、设置／使用／重启入口；只对未完成项提出合适下一步 | 部分成功写成全部成功 |

后台同步只刷新事实，不自动更新或安装插件。验收覆盖双标签、关闭重开、晚到响应、取消与完成同时发生和 Host 中断恢复。
