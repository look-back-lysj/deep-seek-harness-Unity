# EAC Market UI 全面重构设计合同

日期：2026-09-30
状态：阶段 0–5 已实现；当前只剩真实 DSH Desktop 兼容性验收。

## 目标

把当前 Client 从“功能可用的卡片界面”升级为“编辑型插件目录工具”：发现页有明确主视觉和内容节奏，全部插件页是完整可扫描目录，详情/我的插件/任务保持同一套信息层级，动效只解释内容关系和用户动作。

## 不变边界

- 只修改 `packages/market/src/client/**`、`tests/client/**`、`DESIGN.md` 和本阶段设计记录。
- 不修改 `packages/market-core`、Core contracts、Host、Remote、安装计划、任务协议、package.json 或锁文件。
- `CatalogSnapshot.discovery` 是可选投影；缺数据时隐藏区块，不生成假推荐、假评分或假图片。
- 保留官方 DSH 主题变量、原生语义控件、三主导航、真实失败语义、焦点恢复和窄面板 fallback。
- 正式安装入口仍是 mvp.9；本轮只改开发协作分支的 Client。

## 视觉世界

### 页面角色

- 发现页：编辑型精选，低密度、高主次、首推先行。
- 全部插件：完整资源目录，中高密度、可搜索、可筛选、可比较。
- 详情页：单个插件的可信资料页，先价值和主要动作，再事实和资料。
- 我的插件：运行状态和管理列表，强调状态清晰与动作安全。
- 任务/安装计划：操作反馈与下一步，不承担营销展示。

### 表面和层级

- 页面底、内容层、交互层、浮层四类 surface。
- 普通目录条目保持同一平面；只给 Modal、Popover、任务面板和明确浮层 elevation。
- 普通条目减少圆角和阴影，使用边界、分隔线、留白和排版建立层级。
- 主色只用于主要动作、当前选择和真实链接；状态色只表示真实状态。
- 不使用大面积玻璃、固定品牌蓝覆盖官方主题、装饰性发光或持续循环动画。

### 排版和密度

- 页面标题只表达当前任务，不堆多个小标签。
- 首推标题允许大字号和较宽行长；目录标题和条目标题保持清晰但克制。
- 发现页使用展示密度；全部插件使用目录密度；我的插件/任务使用管理密度。
- 各 section 不重复同一种“标题 + 三张等卡片”布局。

## 页面合同

### 发现页

顺序固定为：首推海报 → 推荐皮肤 → 高分插件 → 高分 skill → 规则发现 → 套餐/组合。

- 首推：固定媒体比例；图像、文字、推荐理由和状态同步切换；无图或破图使用同尺寸文字海报。
- 推荐皮肤：横向内容带；没有数据整个区块隐藏；不占首屏大量高度。
- 高分插件/skill：排名式资源列表；评分只显示 Core 真实返回且有来源的值；没有数据不显示。
- 规则发现：只展示少量代表条目；分类只在发现页内筛选；明确点击后才进入完整目录。
- 套餐/组合：放在内容末端，不抢主视觉。

### 全部插件

- 默认展示完整内核目录，用户可切换可安装/全部记录。
- 工具带集中搜索、用途、安装状态、验证状态和排序。
- 条目使用目录密度：名称、简介、作者/包名、状态、一个主操作、一个详情操作。
- 待补资料、缺制品、未验证、硬不兼容和已安装均显示真实原因。
- 目录条目数量少时不能产生大片空洞；数量多时不能横向溢出。

### 详情/我的插件/任务

- 详情：标题和主要动作优先，资料和事实分组，返回恢复来源、滚动和焦点。
- 我的插件：用户插件优先，系统组件折叠；状态、版本、动作顺序固定。
- 任务：逐项状态、错误原因、下一步清楚；不伪造百分比，不用动画代替事实。

## 动效合同

- 交互反馈 80–150ms；分类局部更新 160–200ms；页面/Modal 200–280ms；首推内容切换 260–320ms。
- 首推使用媒体和文字同步替换，不做整页左右飞入。
- 分类筛选只更新规则发现区域，不重播首推和其他 section。
- 页面切换只对内容区域产生一次 opacity/translateY 进入，不改变外层滚动容器。
- 动效可被打断，最终状态立即可见。
- `prefers-reduced-motion` 时关闭自动轮播、位移和非必要淡入；forced-colors 下不依赖渐变和阴影。
- 禁止 `transition: all`、`height:auto` 动画、View Transitions API、backdrop-filter 强依赖和持续循环装饰。

## 数据和后端对接

- Core 继续返回 `CatalogSnapshot.discovery`：`featured`、`recommendedSkins`、`highScorePlugins?`、`highScoreSkills?`。
- 卡片绑定 `pluginId + version`；评分必须有来源且在 0–5；撤回/硬阻断/过期/版本失配不得进入展示。
- Client 不重复实现目录排序、兼容性、安装能力和评分判断。
- 2026-10-02 用户选择试用修复方案 A：首推没有真实精选数据时，允许用现有目录规则得到的少量可安装条目显示“插件探索”文字海报，并明确不是团队精选或评分；不创建或写回推荐数据。真实精选有记录但无图/破图时仍用原尺寸文字海报。推荐皮肤和高分分区没有数据时继续隐藏。
- 不为了填满页面扩展必需 Remote 方法；优先消费已有可选字段。

## 分阶段执行

1. **阶段 0：基线和夹具**：亮/暗、四区块、无图/破图、完整目录、长内容、空/错/待重启场景。
2. **阶段 1：基础视觉系统**：surface、排版、间距、边界、状态、控件。
3. **阶段 2：首推海报**：主视觉舞台、媒体/文字切换、真实动作状态。
4. **阶段 3：推荐皮肤与高分区**：横向带、排名列表、数据为空隐藏。
5. **阶段 4：全部插件目录**：资源列表密度、筛选工具带、完整内核条目、空状态。
6. **阶段 5：详情/我的插件/任务**：统一信息层级、操作区和状态反馈。
7. **阶段 6：动效与兼容性**：所有视口、主题、键盘、forced-colors、reduced-motion、慢/错网络。
8. **阶段 7：完整验收**：pnpm check、browser-check、截图、impeccable detect、真实 Desktop 待验项登记。

## 完成定义

- 首屏可在数秒内理解首推、皮肤、高分和完整目录入口。
- 各内容区有独立布局家族，不是同一张卡片反复复制。
- 发现页不发生隐式跳页；全部插件显示来源和筛选上下文。
- 长文本、空数据、图片失败、Remote 缺能力、暗色、窄屏、键盘和减少动态都可用。
- 所有真实测试通过；未验证的 Desktop/读屏/缩放/真实网络边界明确记录，不用合成结果冒充。
