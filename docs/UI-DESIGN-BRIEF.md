# UI 设计任务书：官方 DSH 内的 EAC 市场

本文件是实施设计建议和验收要求，不是已生成的视觉稿。产品事实以 [PRODUCT.md](PRODUCT.md) 为准。三主导航、高自由度介绍、轻量交互是用户决定；精确视觉参数采用下述推荐默认。

2026-09-28 用户追加确认：采用混合商城，发现页重推荐与图文、全部插件重搜索筛选；“我的插件”默认优先用户可使用的功能，系统内部组件折叠。AI 辅助从相关操作／失败上下文进入，配套有限操作确认，卸载／降级必须单独展示影响并再次确认；详见 [操作守则草案](AI-ASSIST-RULES.md)。旧稿中的原始推荐不能覆盖这些新决定。

同轮追加确认：首页同时保留人工精选和规则排序。建议发现页使用“团队精选”和按用途／兼容性／版本更新时间组织的区块，明确推荐理由或排序依据；全部插件页遵守用户所选筛选和排序，人工推荐不强行置顶。两类内容及空态规则见 [升级计划 v2](UPGRADE-PLAN-V2.md)。

路径遵循实施计划：源码`src/`相对`D:/eac-market/packages/market`；tests、docs、PRODUCT和DESIGN相对工作区根。技能context指向实际包内Client入口，不在工作区根另建第二套UI。

## 1. 设计判断

这是给新手使用的应用页面（Operate），插件长介绍采用阅读模式（Read）。设计目标是「看得懂、装得顺、知道下一步」，不是营销落地页。EAC 页面要有辨识度，但要融入官方 DSH 的主题、控件、侧栏和主面板行为。

推荐方向：**克制的应用商店体验**——准确的字号与留白、细边界、少量蓝色强调、真实截图、稳定的任务反馈。轻重来自内容，而非大面积玻璃、强光晕、背景视频或巨大宣传标题。

备选方向及取舍：

| 方向 | 优点 | 代价 | 本版决定 |
|---|---|---|---|
| 官方风格上的精致应用商店 | 熟悉、轻量、深浅主题兼容，适合频繁操作 | 品牌表达相对克制 | 采用 |
| 大幅图文编辑式首页 | 内容吸引力强 | 需要大量真实素材，容易挤掉搜索和安装入口 | 只在精选区适量使用 |
| 独立炫酷视觉壳 | 风格突出 | 双重导航、重动效和宿主冲突风险高 | MVP 不采用 |

不把守岸人的蓝色视频背景、全屏卡片、Tauri 标题栏搬过来。没有正式 EAC 商标素材时使用文字标识；不得重新包装 DeepSeek 图标暗示官方出品。

## 3. 页面结构与导航

宿主左侧只增加一个 `EAC` 入口，对应独立 main panel；不替换官方「插件」、设置、会话和主页。EAC 页面内部是三个水平主导航：

```text
┌ 官方 DSH 原有侧栏 ┐ ┌ EAC 主面板 ─────────────────────────────────────┐
│ …                │ │ EAC   发现  全部插件  我的插件   任务(2)  帮助  ⋯ │
│ 插件             │ │ 搜索功能、插件或作者…                            │
│ EAC              │ │ 当前分区的内容                                  │
│ …                │ │                                                 │
└──────────────────┘ └─────────────────────────────────────────────────┘
```

- 设置、作者工具和关于页放在 `⋯`，不增加第四/第五个主导航。
- 任务按钮始终可达；有进行中任务显示数量或状态，不使用夸张红点催促。
- 页面导航只影响 EAC 内部视图；不改变当前 DSH 会话、不占用 host 的私有路由。
- 返回插件列表时保留搜索词、筛选器和滚动位置。切出再切回 EAC 时任务仍在 Host 中运行；客户端不拥有安装进程。
- 搜索默认覆盖名称、作者、简介、用途标签；支持中文及英文包名。不做 AI 搜索、不伪造热度。

## 4. 各页面设计

### 4.1 发现

第一屏就能看见：EAC 是什么、推荐内容、搜索/浏览入口和正在安装的任务。没有账号登录遮罩、Star 邀请、付费提示或强制教学。

```text
精选功能，轻松装进 DSH
简短说明（最多两行）

┌ 一个主精选内容：真实截图 + 用途 + 查看详情 ┐  ┌ 上手帮助 ┐
└─────────────────────────────────────────┘  └──────────┘
按用途挑选  [编程] [资料整理] [界面…]  ← 分类来自目录，示意不是预定收录

套餐条目：清楚写包含数量、主要用途和适用环境
精选插件：图标 / 名称 / 一句话用途 / 已安装状态 / 详情
```

只显示真实目录内容：没有有效推荐就展示引导和「查看全部插件」，不填假榜单、下载量、星数或空的推广卡片。最多一处主精选，不自动轮播。无需先完成全部素材才能做功能验收。

### 4.2 全部插件

- 搜索与用途筛选放上方；高级筛选折叠（系统/兼容状态/作者）。
- 列表默认每页 24 个，不一次渲染整个目录；过滤后空结果给出清除筛选操作。
- 卡片只放图标、名称、作者、一句话简介、一个状态和主要操作，技术详情放详情页。
- 验证未知可以展示；「未验证」「已知不兼容」「无可下载制品」必须区分。
- 已知硬性不兼容的安装按钮不可执行并说明原因；未验证项可进入明确确认流程。
- 不符合官方bundle安装格式的条目显示「待作者提供可安装包」，不能把“未验证，仍然尝试”当成绕过格式的方法。
- 已安装条目显示状态/打开，不再误导成重复安装。

### 4.3 插件详情

```text
← 返回
[图标] 插件名称          作者名 / 适用版本
一句话用途              [安装 / 打开 / 完成设置 / 查看任务]
系统及必要使用要求      更新说明 / 来源 / 许可证（展开）

[真实截图画廊，按需加载]

作者自由图文正文                   安装信息（宽屏右列，可选）
标题、段落、图片、列表、表格         目标版本 / 来源 / 大小
教程、示例、常见问题                 验证状态 / 重启要求
```

- 操作区固定、正文自由；作者内容不能改写真实安装状态、伪造验证徽章或提供任意执行按钮。
- 同时只能突出一个主要下一步。已安装但未启用时不能显示「立即使用」。
- 有官方配置导航就打开它；插件无独立页面则显示使用说明；无声明时明确「作者尚未提供使用入口」。
- 作者 Markdown 可以有代码示例，但只复制文本，不执行命令。
- README 相对图片/链接按导入时的仓库与 commit 解析；外部视频先用封面+点击查看链接，不嵌任意 iframe、不自动播放。
- 源文件缺失、图片损坏、超长正文有明确降级；不能让长介绍挡住安装任务或主导航。

### 4.4 套餐确认

这是用户明确同意修改已有版本的唯一摘要页：

| 组件 | 当前 → 目标 | 动作 | 生效方式 |
|---|---|---|---|
| A | 未安装 → 1.0 | 新增 | 按规则启用 |
| B | 1.0 → 1.1 | 升级 | 可能需重启 |
| C | 2.0 → 1.8 | **降级** | 醒目标明影响 |
| D | 1.0 → 1.0 | 复用 | 保留用户状态 |

版本号仅为布局样例，不是实际插件承诺。页面还显示选中/必需组件、未验证项及用户启用意图；不将所有可选内容预选成强制安装。

主操作「按清单安装」，次操作「返回」。发现清单外的版本变化或新增影响时退回重新确认，而不是添加一个模糊的「忽略风险」总开关。

### 4.5 任务抽屉

- 在三页都可打开；进度按真实阶段显示：检查、下载、校验、安装、等待授权、应用、需重启、完成/部分完成/失败。
- 有可靠字节总量时才显示百分比，否则显示阶段和当前组件；不要模拟递增百分比。
- 取消是「正在取消」直到宿主确认；不可取消的应用阶段明确说明。
- 整个套餐成功项保留，依赖失败项显示「等待前置组件」，无关项可继续。
- 前置插件磁盘已升级但尚待重启时，依赖其新运行接口的组件显示「等待重启后继续」；重启核对后展示剩余清单，由用户点击继续，不能暗中重放。
- 构建脚本批准弹窗展示精确包名，并说明「允许设置会保存在当前DSH环境中，后续仍可能生效；本次安装失败也不自动撤回」。批准动作调用专门的task.approveBuilds；权限已保存而安装失败时分开显示。
- 任务丢失或 DSH 重启后先显示「正在核对」，不能瞬间变绿。重试会重新生成/核对计划。
- 技术日志默认折叠；错误摘要包含发生在哪一步和一项可执行处理建议。需要持续处理的错误留在任务中，不只吐一个会消失的 toast。

### 4.6 我的插件

- 展示当前宿主能识别的已安装/随附插件，包含市场外安装者；不等同于「本市场的历史订单」。
- 筛选：全部 / 已启用 / 待设置或重启 / 有更新 / 需处理。更新列表按目录提供的明确目标版本生成。
- 官方不可移除组件显示锁定理由；不提供假的卸载按钮。
- 手动更新前显示当前/目标版本及变更说明。默认保留原启停状态，不能顺手启用用户关闭的插件。
- 卸载确认说明可核实影响，本版不提供未知范围的「清理全部数据」。
- 用户的 link/file/fork 或目录未收录插件可查看官方事实与官方可用操作；不自动替换为目录同名包。

### 4.7 作者编辑工具（次级入口）

- 入口在 `⋯ → 作者工具`，不打扰普通用户。
- 标题、简介、图标、截图用表单；归属对象/版本从目录选取（或在草稿中标为待维护者匹配），只建立介绍对应关系，不修改安装版本与兼容事实。自由正文使用 Markdown 工具栏+编辑/预览切换，宽屏支持左右预览。
- 工具栏至少有标题、粗体、链接、图片、列表、引用、代码块；不是单纯 JSON 文本框，也不是沉重的网页搭建器。
- 自动保存到市场私有草稿区，状态分「保存中 / 已保存 / 保存失败」。离开时未保存内容要提示。
- 导入 GitHub README 到新草稿；覆盖现有草稿前给差异和确认，保留原文链接、提交、导入时间和署名信息。
- 可以追加图片，但安装来源、验证结论等技术字段在编辑器里是只读引用。
- 「导出介绍资料包」输出可被团队校验的文件；Host生成并触发浏览器下载时写「已准备下载」，确认保存后才可写「已导出」，绝不写「已上架」。
- 同时提供「导入本地介绍资料包」，便于作者/团队继续编辑与验证往返不丢内容。
- 文件选择、分块传输、取消、超限与失败都有真实处理；Client不传本机绝对路径要求Host读取。具体通道与体积预算见实施计划§10。
- 本版无在线投稿、作者认证、GitHub 登录和发布按钮；未来 `PublicationPort` 的接口说明放文档，不对用户展示空功能。

### 4.8 设置与轻教学

设置只包含真正有用的项目：目录刷新/离线状态、下载来源偏好（自动优先）、缓存容量与非使用中下载缓存清理、外观遵循宿主、重看教程、导出诊断。

首次说明不超过三步：「找功能 → 安装 → 开始使用」，可跳过、可在帮助重看。首次安装不要求先看教学；术语解释就近出现，例如「需要重启：新版本已保存，下次启动 DSH 才会使用」。

不要加 Star 提醒设置、作者登录开关或发布服务地址输入框来假装完成后续能力。

## 5. 视觉规格（建议默认）

- 以官方 `--dsw-font-family` 字体栈为主；简体中文不加载远程字体。正文 14–15px，列表标题 16px，页面标题 24px 左右；正文行高 1.5–1.7。
- 复用 `--dsw-alias-bg-base`、`--dsw-alias-bg-layer-*`、`--dsw-alias-label-primary/secondary`、`--dsw-alias-border-l*`、`--dsw-alias-link`。准确可用项在实施 M0 对目标官方包验证。
- 仅在 `.eac-market` 根作用域定义市场变量；深色由宿主主题决定，不向 `body/:root` 写全局替换。
- 一种蓝色强调用于主操作/选中，成功/警告/错误使用语义色并配文字。不能把所有 badge 都涂成品牌蓝。
- 内容宽度上限约 1200px；面板内边距 24px，小面板 16px；间距采用 4/8/12/16/24/32。
- 按钮最小高度 36–40px，触摸窄屏采用 44px；圆角继承官方 8/12/16 尺度；阴影只区分弹层，不层层卡片套卡片。
- 主导航一直清楚，状态和首个操作不被巨大标题挤出首屏。长包名、长作者名、中文/英文混排不得横向撑爆。
- 过渡优先 150–200ms；无背景循环视频、无页面入场编排；减少动态效果时关闭非必要运动。
- 图片延迟加载、保留宽高比例、失败显示文字替代；截图放大使用宿主图片浮层或等效可键盘关闭组件。

## 6. 窄面板与可访问性

不能只用浏览器窗口宽度判断布局：DSH 侧栏/右面板会压缩市场可用宽度。优先容器查询。

| 市场内容区宽度 | 布局 |
|---|---|
| ≥1000px | 发现区主精选+辅助区；插件 3 列；详情可双列 |
| 720–999px | 插件 2 列；详情改为单列 |
| <720px | 一列内容；搜索独占一行；次级操作收进菜单 |

验收外窗至少 1440×900、1280×720、960×640，并通过宿主分栏制造约 480px 内容区。深浅主题各一轮；键盘 Tab/Enter/Esc、焦点恢复、120–200% 缩放、读屏 label、无结果/失败/长文全部检查。

正文与主要按钮文字对比至少 4.5:1；颜色不是唯一状态线索。弹窗有标题、焦点约束，关闭返回触发按钮。进度用适当 aria-live，不能每个日志行都打断读屏。

## 7. 轻量与性能预算

这些是待验证的工程预算，不是已测结果：

- 官方 React/Cordis/UI primitives 复用宿主，不再打入一套。
- 市场浏览核心新增 Client JS 初始 gzip 目标 ≤250 KiB；作者编辑器按需载入，不阻塞普通浏览；超预算必须有依赖分析，不能直接删功能掩盖。
- 不引入 GSAP、Three.js、额外应用壳、全量富文本平台、聊天模型或常驻云服务。
- 1000 条测试目录时输入筛选反馈目标 ≤200ms（记录设备与测量方法）；描述和大媒体按需读。
- 未打开市场时不轮询全目录；任务激活时订阅官方事件并做有界补偿读取。离开页面卸载订阅/observer；后台安装归 Host。
- 连续 50 次开关市场无累计事件监听、定时器和重复 slot；截图、CPU/内存数据必须出自测量，不凭感觉写「占用很低」。

## 8. 给 UI 子智能体的可复制提示词

```text
你负责官方 DSH 内 EAC 市场的 UI，不是另做一个网站或桌面壳。
先读 PRODUCT.md、UI-DESIGN-BRIEF.md、共享 contracts 和 docs/host-capabilities.md。
调用 impeccable，采用 Operate/Read 模式；优先官方主题与导出控件。
不得把 design-taste-frontend 的营销 Hero、随机风格、重动画强加到此应用。
```
