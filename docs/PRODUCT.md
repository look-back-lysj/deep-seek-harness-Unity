# EAC 插件市场：已确认的产品约束

<!-- impeccable:product-schema 1 -->

版本：接力需求 v2；最近整理：2026-09-28，保留 9 月 27 日已定范围。本文是需求事实源，不表示已经完成开发。

## Platform

web

运行在官方 DSH 的客户端界面内；优先交付并实测 Windows x64 官方 Desktop。它是标准 DSH 插件，不另建 Electron/Tauri 壳，也不复活旧 EAC 的 window.dshDesktop 桥。其他系统和普通 Web 形态保留适配边界，未实测不得标为已支持。

## Stack

方案建议：TypeScript + Host/Client 双入口；复用官方 Cordis、UI slots、远程服务、插件管理、React 和 UI primitives。编译工具链沿已读取官方版本及团队安装器的契约收口。用户授权本计划设计技术细节；具体锁版本由实施 M0 查证写入基线，不用猜测的版本号。

## Users

- 第一用户：刚接触 DSH、不懂包名、命令行和依赖管理的新手。
- 次级用户：合作插件作者、代录入介绍的团队成员、后续维护者。
- 不要求普通用户拥有 GitHub 账号才能浏览和安装公开插件。

## Product Purpose

EAC 转型的第一步：依托官方 DSH，把 EAC 的整合价值组织成独立市场插件、精选组合与可维护目录。用户能理解用途、安装功能、完成必要设置并找到使用入口。

市场同时支持套餐和单插件；未来能接入现有 EAC 插件功能、自研插件和外部作者。旧功能只是接入目标，不等于已兼容、允许搬运全部代码或必须默认启用。

当前官方Desktop的一键安装入口要求有效 `dsh.bundle.patch`。MVP的一键安装限符合该入口的bundle包；普通Host/Client源码包可展示，作者补加载声明或独立包装包验收后再安装。此为已查证的官方能力边界，不是另造EAC私有插件标准。

## Confirmed decisions

1. 市场是 DSH 内一个完整 EAC 页面；主导航只有「发现 / 全部插件 / 我的插件」。帮助、任务、设置和作者工具是次级入口。
2. 先实现市场核心。正式首批收录名单、全家桶内容及分发打包另行安排。
3. 未来先提供基础功能随包可用、其余按需下载的形态，也保留完整离线包的选择。
4. 市场代码与目录资料分开维护；随包基础目录、在线更新目录和最近可用缓存共同工作。目录更新不安装或更新用户插件。
5. 多下载来源服务于简便：普通用户只点安装，市场处理经核验的同版本来源；不能静默换成旧版或同名别包。
6. 套餐安装先显示版本调整清单，用户一次确认后可按套餐要求升级或降级。安装失败保留成功项，继续不受影响的组件；相关依赖项暂停，整套不能假报成功。
7. 未在当前环境验证的插件可明确选择「仍然尝试安装」；不绕过已知硬性不兼容、产物校验或官方安全限制。
8. 首版支持用户手动更新。没有静默后台更新；要保留已有启停选择并说明重启要求。
9. 默认启用按能力及既有分发规则处理；额外权限、账号、大资源下载需要必要引导。不能自行发明分发类别或把 external 直接标为不可信。
10. 作者正文采用高自由度图文，支持在市场内编辑、GitHub README 导入、预览与导出资料；固定信息区负责真实版本、来源、兼容与安装状态。
11. 最新范围修订：作者在线投稿、认领、首次审核后的自行发布全部后置。MVP 交付作者本地编辑/导出和团队私下接收资料的流程，不建设账号服务器，不提供假的在线投稿。
12. Star 全部后置：MVP 无 Star 弹窗、写权限、自动 Star、提醒开关或登录门槛。未来恢复该功能时仍须尊重此前「用户主动支持、设置控制提醒」及 GitHub 平台规则。
13. 要求结构清楚、必要注释齐全、总目录、接口说明、升级指南、验证记录和下一模型可复制的多子智能体提示词。
14. 2026-09-28 体验复核后的用户确认：商城采用混合结构，发现页侧重真实推荐和图文，全部插件侧重搜索与筛选，继续保留三个主导航。
15. 同轮确认：增加 AI 辅助诊断，并支持用户确认后执行有限操作；必须配套既有约束作用又有操作指引的守则。允许范围包括安装、更新、已登记同制品换源重试和普通插件启停，并允许提出卸载、降级方案；后两类必须单独展示影响并再次确认。不能将这一方向理解为任意命令、自动提权或任意文件修复授权。当前方案见 [AI-ASSIST-RULES.md](AI-ASSIST-RULES.md)，尚未实施。
16. 同轮确认：“我的插件”优先展示用户可使用的功能，系统内部组件默认折叠到“系统组件”；分类不能掩盖实际启停、版本和失败事实。
17. 同轮确认：首版 AI 采用 Host 直接调用 DSH 当前默认模型的无工具分析，模型返回提案，市场校验后执行用户确认的方案；不建设专用 Agent 会话，不让模型自由探索电脑。实际接口、允许范围与验收见 AI 操作守则。
18. 同轮确认：首页推荐同时保留团队人工精选与基于兼容性、用途、更新时间的规则排序。两者都只使用已收录的真实内容；人工推荐附理由，自动结果说明排序依据。团队精选不应覆盖用户主动选择的搜索或排序条件。

## Explicit defaults, not past user approvals

- 卸载数据问题未获明确回答：MVP 采用保守默认，仅调用必要卸载能力，不额外清理独立配置、用户文件或未知目录。不能保证第三方插件自身卸载行为保存所有数据，应事先说明可核实的影响。
- MVP 不提供任意链接/任意路径的一键安装框；先把目录驱动安装与验证过的本地制品安装链走通。后续扩展入口不改变核心任务协议。
- 首个正式实测目标为本机已发现的官方 Desktop 0.1.7-rc.2 / Windows x64。版本变化由 M0 重新核对，不把此版本等同永远最新版。
- UI 以官方视觉系统和轻量应用界面为基础；精确视觉参数是本计划建议，不冒充用户已经选择的设计稿。
- 不增加支付、评论、评分榜、广告系统、云同步、整机守护或自动系统修复。

## Operating Context

官方 Desktop 的 profile 为 `profiles/desktop`；旧 EAC 的 `web-desktop` 不是通用路径。实际目标必须由当前宿主提供并绑定，不能扫描电脑后猜一个目录。

测试在独立目录/独立实例中完成；CLI 冒烟不能替代官方 Desktop 验收。用户电脑上的旧 EAC、全局 dsh、真实会话、API Key、Skill 和守岸人仓库不属于本任务修改范围。

## Brand Commitments

- 品牌文字为 EAC，定位为社区整合市场，不暗示 DeepSeek 官方认证。
- 高级、美观、简洁、容易使用；不把技术字段堆给新手。
- 原作者署名、原链接和许可证保留；截图和验证结论不能编造。
- 守岸人备份程序的动态视频背景不是本市场的既定设计要求。

## Evidence on Hand

完整路径、提交、实际接口及资料优先级见 [PROTOCOL-EVIDENCE.md](PROTOCOL-EVIDENCE.md)。官方源码是解压目录，不含 `.git`；只能证明已读取文件内容与其版本，不能捏造它对应的 master commit。

## Product Principles

- 页面说成功，必须有对应事实；安装、启用、界面加载和业务可用不是同一件事。
- 当前环境由宿主确定；介绍内容和目录数据不能授予写其他环境的权限。
- 内容更新与可执行制品更新分开，历史兼容证据不被改成新证据。
- 任务失败可解释、可复查；不承诺未经实证的整体回滚。
- 快速交付来自复用与并行边界，不来自删掉失败处理或只做演示按钮。

## Accessibility & Inclusion

简体中文优先，保留英文词典结构；键盘可操作、可见焦点、文字对比达标，状态不能只靠颜色；支持浅色/深色、减少动态效果和缩窄的 DSH 主面板。
