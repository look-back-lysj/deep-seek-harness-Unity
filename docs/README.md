# EAC 插件市场 MVP · 实施交接计划

> **历史 v1 文档。当前代码已经存在。** 继续工作请先读 [2026-09-28 下一模型接力入口](handoff/START-HERE.md)。下文“尚未编写代码”等语句只描述当时状态，旧提示词不能覆盖新产品决定、实际缺陷与执行顺序。

这套文档把前面的产品讨论整理成下一模型可执行的开发任务，目标是做出**官方 DSH 内的 EAC 市场插件**：轻量、好看、好理解，能可靠安装并管理插件，方便后续接回 EAC 功能和合作作者。

版本：v1；日期：2026-09-27。**当前交付是计划与提示词，尚未编写市场代码或运行市场测试。** 本轮读取了本机官方DSH源码、EAC当前refs/团队交接、Mojobox协议及本地设计技能，使用了两位只读探索子智能体；计划还需以实际官方Desktop打包验证解除已列的不确定性。

## 3. 为什么这样安排

已有安装器可以提供参考，但发现过：漏打包类型运行文件、摘要没有贯穿实际安装、首次失败提前结束、CLI分支丢启用意图、结果缺字段默认成功等问题。因此先用很小的真实插件包确认官方Host/Client都能运行，再让多人并行写功能。

开发分成三个可检查成果：**真实单插件闭环 → 完整市场与作者工具 → 最终包官方Desktop验收**。每阶段完成定义写清楚，减少写了很多页面最后接不上的返工。市场不自造包管理器，尽量复用官方现有能力。

选型表保留其他方案的优缺点；精确技术默认值属于本版建议，不冒充用户每一项都已选择。接受计划后可按建议持续实施；出现会改变产品范围/权限的新选择再沟通。

## 5. 当前还不能声称已经解决的事项

- 独立市场包的Typert生成、peer解析和官方Desktop加载需M0实验，源码调查不能代替运行。
- 同一机器第二次打开Desktop可能聚焦已有窗口；必须证明profile/userData隔离，才可测试安装。
- 正式GitHub/Gitee制品地址、首批合作插件及其许可/兼容证据仍待后续收录确认，不能凭空生成。
- 官方管理器可能只恢复部分元数据，不能因此宣传完整回滚；断线与崩溃后的未知状态必须如实展示。
- 多源下载能改善可达性，不能保证任意网络/未来版本永久可用；未完成的系统与版本测试要写清楚。

这些都有明确解除步骤和验收项，属于可执行计划中的工程门槛，不是留给下一模型随意猜测的空白。

## 6. 本轮计划审查记录

两位只读探索员分别核对官方DSH接入和团队协议；主控核对关键源码并编写文档；独立Reviewer实际读取全部八份文档，发现五项可行动缺口。已修订并经其定向复核：

| 初轮缺口 | 修订结果 |
|---|---|
| 套餐组件依赖没有事实源 | 私有PackExecution绑定Lock，明确完整/未知及installed/active条件，不改公共协议 |
| 脚本批准后没有继续接口 | 增加approveBuilds/resume及挑战绑定、幂等规则 |
| 任务排队后可能沿过期清单执行 | 同plan唯一task，出队/每步写入/批准/重启继续前复查 |
| 前置插件待重启，后续仍可能被启用 | 运行前置未满足就暂停；重启核对后由用户继续 |
| 授权持久影响未写明 | UI说明授权持续生效；分开记录“权限已保存”和“安装失败” |

主控另补充：官方bundle限制、Typert实际生成目录与产物、缓存file依赖归属、原有启停保留、作者文件通道及范围控制。文档链接、代码块与编码检查通过。
