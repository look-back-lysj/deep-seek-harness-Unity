## 3. 页面设计与交互规格

### 发现

第一屏保留轻量搜索和三个主导航，主要内容是一个有真实截图的精选位置、按用途的集合、适合新手的基础组合。推荐必须给出简短理由，例如解决什么问题、需要什么设置；没有真实内容时用准确空态，不编榜单或用户数。

推荐位置属于市场自己的展示资料，与 `builtin/recommended/external` 分发分类分开。点击用途后进入“全部插件”并实际带上对应筛选；详情返回时保持来源、搜索和滚动位置。教学只作为轻量次级入口，不占据每次访问的大半首屏。

用户已确认两种推荐机制并存。具体展示建议如下，布局参数仍属设计稿：

- **团队精选**：由团队维护位置、排序和具体推荐理由，标注“团队精选”；不将人工选择等同官方认证或当前环境已验证。
- **按规则发现**：提供按用途、当前环境兼容情况、插件版本更新时间组织的区块或列表，标明实际依据；不使用 AI 猜测热度，不读取用户项目或会话来做个性化推荐。
- 两类推荐的记录分开维护，可以引用同一个插件；同一首页重复出现时优先合并展示，保留两种推荐依据。没有人工内容时仍可展示真实的规则结果，不把它伪装为团队精选。
- 用户在“全部插件”选择搜索／分类／排序后，严格遵守该选择，人工置顶不混入覆盖结果。返回列表保留选择和滚动位置。
- “最近更新”采用有来源的插件版本发布时间；只改介绍、镜像或推荐位置不提升版本新鲜度。没有可靠时间的条目明确标未知；同分结果按稳定标识排序，避免列表跳动。
- 推荐不改变安装条件。当前版本不兼容、证据失效、制品撤回或目录缺失时，展示状态与入口按真实事实调整；不能因人工置顶而绕过检查。

### 全部插件

名称、用途、作者、简短安装状态为主要信息。版本、来源、许可与证据可以展开查看。区分三种空态：尚无收录内容、目录加载失败但有旧缓存、筛选无结果。列表不能用一个“没有匹配”掩盖这三种情况。

已安装且目录有更高版本时提供“更新”，同版本提供适用的下一步；未验证需用户明确勾选，已知硬不兼容保持不可安装。不要把包内缺加载声明视为可通过“仍然尝试”解决。

### 详情

优先顺序：名称及作者 → 一句话用途与主操作 → 真实截图 → 使用步骤／设置要求 → 作者自由图文 → 可展开的技术详情。小面板不得把技术信息排到名称前面。

主操作由真实状态决定：可安装、正在处理、已安装未启用、需设置、可打开、可更新、需重启或状态待核对。缺少公开打开／设置接口时显示准确指引，不保留无点击逻辑的按钮。

### 我的插件

优先呈现有用户功能入口的插件与已安装社区插件；提供名称、用途、当前版本、状态和可用操作。系统组件折叠，仍可展开查看，加载失败不能被折叠逻辑隐去。

分组依据需要来自官方元信息及经维护的市场内容，不能只看 `@deepseek-ai` 前缀就把官方有用功能全部藏起来。来源、功能分类、官方是否允许操作各自独立；不在市场目录中的插件也保留官方可核实信息。

### 安装与任务

点击安装后自动进行只读预检，展示含目标名称与版本的清单；用户确认后才安装。目标、勾选或环境变化使旧清单失效。下载、校验、安装、等待授权、需重启、完成／部分完成／失败分别展示真实状态，不显示没有依据的百分比。

进度可以在卡片中简要显示，任务详情提供取消、查看原因、重新核对或重试。只有仍在进行且可取消时显示取消按钮；失败记录保留并关联新的重试，不通过清记录解除冲突。

### AI 辅助

在失败任务、不能启用或不能更新的上下文提供“AI 帮我处理”。分析区展示原因、证据和候选方案；确认区展示实际操作和影响。卸载／降级按守则增加独立影响确认。普通市场在 AI 不可用时仍可完整使用。

### 作者工具

次级入口下提供草稿列表、编辑、预览、图片管理、README 导入和真实介绍 ZIP 导入／导出。首次导入可以直接创建新稿；覆盖现有稿须提示并使用用户看到的 revision 防冲突。再次打开能取回保存稿。

## 5. 关键技术约束

- **计划与确认**：新计划有独立编号，旧计划不可被覆盖；摘要锁住展示过的目标。相同计划重复提交复用任务，新重试关联旧任务；运行中等价意图仍需防重。
- **状态**：配置已启用、文件已安装、当前进程已运行、业务验证通过四者分开。宿主版本／会话身份必须有实际来源；库存数量不能作为“确实已重启”的证明。
- **取消与并发**：写协调不等于把取消信号排在安装完成后。取消及时送官方服务，落盘时防止旧记录回写覆盖终态；跨工具状态变化复查，不能声称完全锁住官方外部操作。
- **来源与缓存**：同摘要镜像共享目标，校验通过的文件就是实际安装文件；检查仍被 `file:` 依赖引用的缓存，不能因清理空间破坏已装包。
- **目录发布**：校验成功后写完整快照，持久提交完成才切换展示与 Lock 的内存版本；读取失败继续旧快照并如实标识。
- **证据**：执行目标系统、宿主版本、制品摘要、测试范围、时间和撤回状态决定验证结论；单独的 `verified` 字符串不能升级成“当前环境已验证”。
- **作者资料**：媒体统一身份与读取通道；正文、附件、出处、署名和许可证完整往返。介绍资料 ZIP 与插件安装包明确区分。
- **AI**：程序校验允许操作、确认来源、参数范围、权限和状态；模型仅提案。原始工具权限不能因提示词一句“禁止”就视为已受限。
- **协议升级**：本轮修改确认、诊断、能力和任务接口，须由主控明确兼容范围并更新握手、运行时校验与生成产物。新 UI 遇到旧 Host 或缺 AI 能力时按能力降级，不能仅凭方法名存在就启用执行按钮。

## 6. 内容接入与未来整合包

先做内容维护的样例流程，不预先塞入旧 EAC 全部插件。首批真实样本需要作者或维护者确认许可、对应发布包和实际入口。至少覆盖一个可安装标准包、一个暂不可安装但可展示条目、一个多组件组合。

内容生成管线应检查：官方加载声明、Mojobox 固定版本格式、版本和摘要关系、镜像同字节、依赖清单、作者资料、证据及推荐位置。一个内容变更应能独立审核，不需要修改安装算法。

未来基础包由同一已核验清单生成，预装内容与推荐内容分开；用户已有禁用／配置选择需保留。完整离线版另验插件所有依赖及许可，不能把顶层 tgz 齐全等同离线闭包齐全。

人工精选与规则排序已确认同时保留。内容 Worker 维护独立的精选记录、排序所需的真实元数据及来源，UI Worker 负责明确标签和排序控件；公共分发分类与验证证据不被推荐位改写。内容仓由谁审核和发布仍需与团队确认，暂不建设新的作者账号服务器。

## 7. 多智能体的文件所有权

W=`D:/eac-market`，P=`W/packages/market`。下列 `src` 相对 P，测试与文档相对 W。最大三名 worker 并行，强依赖串行。

| 负责人 | 独占写范围 | 不可自行改 |
| --- | --- | --- |
| 主控 | contracts、host 组装、Host 入口、package／锁、构建打包、总目录 | 官方源码、组织仓库、用户真实 profile |
| 安装 Worker | core、persistence、主控划定的管理 adapter、对应测试 | UI、目录资料、共享 DTO 与 package |
| 内容 Worker | catalog、delivery、authoring、相应 tests、内容维护说明 | 公共 Mojobox 协议、安装状态机、UI |
| UI Worker | client、Client tests、DESIGN | Host 执行器、共享 DTO、模型授权规则 |
| AI Worker（S4 替换已完成名额） | 主控划定的 AI 模块及官方模型 adapter、相应 tests | 重写官方安装器、放宽允许列表、抢改 UI/Host 共享入口 |
| QA | 专用验证实例与 integration tests、证据 | 业务代码、用户日常环境 |
| Reviewer | 默认只读；独立核查源码、包和证据 | 为消除失败修改测试期待或业务实现 |

共用文件变更由 worker 提出准确请求，主控修改；不让两个 worker 同时编辑 `MarketPage.tsx`、contracts 或 package。基于修复后的最终状态重新写文档，历史阶段报告保留日期和范围。

## 9. 交付门槛

新增 UI 性能目标保留原稿的核心 JS gzip 预算与大目录筛选目标；先实际测量再填写结果，不能由动画时长推导流畅。没有新增业务代码的本轮不重跑构建或宣称这些指标已达成。
