# MVP 验收矩阵

**本表是未来要执行的测试设计，目前市场尚未实现，所有条目均未执行。** 表中的「必须」是交付门槛，不是已通过。基线、包摘要和环境信息必须写进实际报告。

每条用 `pass / fail / blocked / not-run` 标记；Mock、真实服务、真实 Desktop 证据分别标明。出现阻断问题后由所属worker修复，不能只改断言或跳过测试。P0/P1未关闭不得标MVP完成。

## 1. 测试分层

| 层 | 能证明什么 | 不能证明什么 |
|---|---|---|
| U：纯逻辑/组件 | 计划、状态、Schema、错误与UI状态可重复正确 | 实际宿主服务和最终包一定能运行 |
| P：打包检查 | 包内文件、exports/schema、依赖和许可证齐全 | Client在真实Desktop能渲染 |
| I：隔离官方服务 | 官方管理调用、文件变化、重启语义 | Desktop UI交互和原生恢复体验 |
| D：隔离官方 Desktop | 最终包在真实官方软件中的端到端行为 | 未测试系统/宿主版本也能运行 |

这是本次标准插件的验收层次，不沿用旧EAC V1–V5的测试数量。若以后改EAC资源装配/安装器，另按该仓库影响矩阵补检，不能拿此表替代。

## 2. 环境与测试输入先准备

- 新建专用 `D:/eac-market-verify/<runId>`，记录允许修改的根、宿主版本、最终tgz SHA256。
- 证实实际启动程序、DSH_HOME/profile、Desktop userData、端口和进程归属；出现单例转发或路径混淆立即停止测试写操作。
- 使用自建、无害的标准测试bundle A v1/v2、B依赖A、C独立、失败包F、需脚本许可包S。不要把真实坏插件或破坏用户目录当测试方法。
- 测试目录与两个可控HTTP端点用于断网/镜像/篡改模拟；生产仅允许受控HTTPS。测试开关必须不可被生产远程目录打开。
- 用两个独立profile验证隔离；模拟权限不足、磁盘不足和文件锁在专用目录实现，真实环境演练与mock要分开写。
- 选一个有真实许可和可下载制品的社区插件做实际体验抽样；如暂未确定，只能说明真实第三方体验项待验，不能伪造收录名单。

## 4. 状态文字必须与底层事实对应

| 用户看到的文字 | 至少需要的证据 |
|---|---|
| 已下载 | 文件完成写入；不代表校验通过 |
| 已校验 | 与已确认摘要相同，包身份符合计划 |
| 已安装，未启用 | 官方安装与inventory一致；enabled为false |
| 已应用 | 官方明确applied，库存与目标相符；不承诺业务已验证 |
| 需要重启 | 官方restart-required或可核实的待生效事实 |
| 部分完成 | 部分组件成功，其他失败/暂停/取消，明示数量与后续 |
| 已取消 | 官方取消/进程与状态结论明确；不把此前成功项称为撤销 |
| 正在核对 / 无法确认 | 断线、未知返回、Host中止或磁盘变化导致缺证据 |
| 当前环境验证通过 | 真实Evidence绑定当前制品、Host/系统范围与suite；不是测试fixture |
| 已准备下载介绍资料 | Host生成资料实际可读并通过schema；浏览器最终保存需另有证据，不表示在线发布 |

## 5. 完成报告模板

```text
测试批次/时间：
市场版本、源码commit（若有）、最终tgz SHA256：
官方DSH版本、归档/发行包身份、系统/架构：

用例ID | pass/fail/blocked/not-run | U/P/I/D | 操作 | 实际结果 | 证据位置
已修复的问题及重新验证：

```

**完成门槛**：范围内关键流程没有P0/P1；P/U/I必需项通过；D必需项有真实证据；未覆盖的系统/版本写清楚。若当前工具无法控制官方Desktop，先完成其他可做项并提供运行包/准确测试步骤，报告 `partial：官方Desktop待验收`，不能降低门槛悄悄签字。
